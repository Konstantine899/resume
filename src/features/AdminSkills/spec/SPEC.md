## Цель

Переработать админ-блок «Навыки» (`/admin/skills`) по продуктовому запросу: **отдельная таблица на каждую категорию**, у каждой таблицы — контрол «фильтрации по количеству элементов» в шапке и пагинация; заданное поведение кнопок «Добавить категорию», «Добавить технологию», «Редактировать технологию»; описанное модальное поведение Save/Delete. Поведение, не зафиксированное запросом и не вытекающее из текущего кода, помечено как **Требует уточнения (OPEN)** или **Предположение (A)**.

### Внешний вид действий (rev.3, эпик skills-actions-polish) — РЕШЕНО (вердикт 2026-10-12)

Все 7 кнопок действий из таблицы выше конвертируются из текстовых kit `Button` в kit `IconButton` с kit `Tooltip`; кнопки МОДАЛКИ подтверждения («Отмена»/«Удалить») остаются текстовыми.

- **Композиция:** `<Tooltip content={t(key)} position="top"><IconButton icon={<Icon name={…} size={20} color="inherit" decorative />} ariaLabel={t(key)} variant/size как у текущих Button} … /></Tooltip>`; `ariaLabel` и тултип — ОДИН И ТОТ ЖЕ существующий i18n-ключ (новых ключей нет — вердикт OPEN-3=A плана).
- **Иконки (lucide-react):** `Plus` — добавить категорию/технологию; `RotateCcw` — сброс; `Pencil` — редактирование; `Trash2` — удаление. Паттерн — `MyWorkEditorList.tsx:228-241` (kit `Icon`-обёртка, `inferIconSize` доресайзивает).
- **Размеры:** строки и шапки блоков — `size="sm"` (32×32, ≥24px WCAG 2.5.8 — подтверждено `IconButton.module.scss:65-73`); шапка страницы — `size="md"` (40×40), как header MyWork.
- **Варианты:** сохраняются 1:1 от текущих кнопок (outline/primary/danger — вердикт OPEN-4=A); `variant="danger"` — семантический алиас kit (primary + colorScheme danger, `resolveButtonAppearance.ts`), руками не переписывать.
- **Правый прижим (вердикт OPEN-1=A):** шапка блока — `justify-content: flex-end`; ячейка «Действия» — `margin-left: auto`/`flex-end` через класс `.actions` в `SkillsEditorList.module.scss`. DataTable колонки `align` не имеют — CSS на потребителе, kit не правится (вердикт OPEN-3 плана). Соседние списки (MyWork/Jobs) прижима не имеют — Skills первый, их не трогаем.
- **Card-границы блока (вердикт OPEN-2=A):** `<section>` категории → kit `Card` `variant` default + `size="default"` (padding 16px) + `hoverable={false}` (гасит hover-lift `Card.module.scss:17-21` через `.noHover`) + `className={styles.block}` с `height: auto` (базовый миксин фиксирует 220px — `_card-mixins.scss:4`); `data-testid="skills-category-block-*"` пробрасывается restProps'ом. Заголовок страницы (h2+hint+header-иконки) остаётся СНАРУЖИ карточек. Админ-прецедент — `StatCard.tsx:22`.
- **Tooltip:** `position="top"` пиним явно; kit `autoAdjust` (types.ts:48-49) не отключать — правый край вьюпорта; **trigger = hover (дефолт kit)** — RED-тест закрепляет hover/unhover; focus-визуал НЕ открывает тултип (см. A14), имя кнопки на focus несёт `aria-label`.
- **Тесты:** существующие `getByRole('button', { name: <ключ> })` переживают (ariaLabel = прежний ключ); добавляются тесты видимости тултипа по hover/unhover.

### Модальное окно формы (create/edit) — РЕШЕНО (вердикт 2026-10-10)

> Вердикт владельца (OPEN-2: «переносить однозначно»): формы создания/редактирования переносятся в `Modal` (сегодня они инлайн под списком).

- **Открытие:** по кнопкам выше; `isOpen=true`; контент — существующая RHF-форма (валидация zod, `disabled={!isDirty}` на Save — факт).
- **Закрытие:** «Отмена» (`skillsCancel`) / ESC / клик по оверлею (`closeOnOverlayClick`) → `isOpen=false`, изменения не сохраняются, без подтверждения о несохранённых правках (A8). Успешный Save тоже закрывает (A7 — отличие от текущего create-поведения, где инлайн-форма оставалась открытой).
- **«Сохранить» (`skillsSave`, submit):** 1) zod-валидация (ошибки — `Paragraph role="alert"`, ничего не сохранено, модалка открыта); 2) `persistSkills(next)` → `false`: тост `skillsPersistError`, модалка открыта, состояние стора не тронуто; 3) успех: dispatch add/update → тост `skillsSaved` → закрыть модалку. Порядок persist-THEN-dispatch — обязательный (факт текущего контракта).

### Модальное окно подтверждения («Удалить»)

- Открытие: «Удалить» в строке технологии (`kind:'technology'`) / действиях категории (`kind:'category'`) / «Сбросить» (`kind:'reset'`) — как сегодня.
- Содержимое: title `skillsDelete`/`skillsReset`; текст подтверждения передаётся через **`subtitle`** модалки (kit `ModalRoot` строит `aria-describedby` только из него — `ModalRoot.tsx:44`, иначе у кнопки «Удалить» нет связанного описания, GitHub Primer Accessibility); кнопки «Отмена» + danger «Удалить» (`loading` во время persist), фокус после открытия — на «Отмена» (destrucive-confirm паттерн).
- Называние: текст подтверждения (через `subtitle`) **называет удаляемую сущность** — «Удалить React?»; для категории — текст уточнения OPEN-4 (технологии удаляются вместе + количество при N > 0) с именем категории (вердикт OPEN-10 «Вариант А»). Кнопка остаётся короткой **«Удалить»** (`skillsDelete`), «Отмена» — прежняя.
- «Удалить» (confirm): `persistSkills` списком без цели → dispatch `deleteTechnology`/`deleteSkillCategory` → тост `skillsDeleted` → закрыть.
- Ошибка storage при confirm: тост `skillsPersistError` + **модалка остаётся открытой** (вердикт OPEN-9 «унифицируем» — единообразно с формой, можно повторить); данные не изменены.
- Семантика категории: технологии удаляются вместе с категорией (факт); текст подтверждения для категории уточняется (вердикт OPEN-4): отдельный ключ сообщает, что технологии категории тоже будут удалены, и при `N > 0` показывает количество (ru-plural `_one/_few/_many`, `{{count}}`); для категории без технологий — без количества. Удаление технологии и сброс — прежний `skillsConfirmDelete`/`skillsResetConfirm`.
- «Отмена»: закрыть без изменений.
- Все ветки колбэков defensive (проверяют сопоставимость kind/цели до dispatch) — уточнение контракта A12 («открытая форма относится к удалённой записи» недостижима, пока модалки mutually exclusive), факт тестов `SkillsEditorList.test`.

### Загрузка иконки (rev.2, эпик skills-icon-upload)

- **Направление (вердикт OPEN-1 = A):** полная замена. В `TechnologyForm` Select `iconSvg` (62 ключа `SKILL_ICON_KEYS`) удаляется; новая иконка — только загрузка SVG-файла через kit `FileUpload`.
- **kit FileUpload: raw-SVG passthrough.** При `file.type === 'image/svg+xml'` хук `useImageDragDrop` НЕ идёт в canvas-пайплайн (растеризация убивает вектор; dimensionless SVG → naturalWidth 0 в Firefox): проверка капа байтами (в вызове формы ~50 КБ → `tooLarge`), дешёвая санити-проверка текста (содержит `<svg`; не содержит `<script`/`javascript:` → `undecodable`), отдача **исходного File** как blob + objectURL-превью. Растер-путь (не-SVG) не меняется. A2: без собственных строк — коды ошибок/тексты через `texts` потребителя.
- **Хранилище.** Паттерн ProjectForm (PR #209): `isDirectoryPickerSupported()` → нет: тост unsupported, форма без иконки (Chromium-only риск принят владельцем 2026-10-10); root-handle в IndexedDB `imagesRoot`; `getOrCreateSubdir(root, 'skills')` + `saveImageToDir(root, blob, name, 'skills')` → **путь** `/images/skills/<имя>` в `setValue('iconSvg', path, {shouldDirty, shouldValidate})`; AbortError молча (дисклеймер picker'а); прочая ошибка → тост save-error, значение не тронуто.
