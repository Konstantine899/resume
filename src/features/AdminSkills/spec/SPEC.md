# SPEC — features/AdminSkills (редактирование блока «Навыки»)

> Единственная истина для этого блока (spec-driven workflow: AGENTS.md, раздел Spec-driven features). Статусы: `draft` → `approved` → `done`.
> Исходный план: vault `wiki/plan/plan_admin_panel_edit.md`, rev.3 (фаза 1 — блок «Навыки»). Companion: [TODO.md](./TODO.md).
> Язык: русский (правило владельца). Все user-facing строки в коде — i18n-ключи en+ru.

## Цель

Переработать админ-блок «Навыки» (`/admin/skills`) по продуктовому запросу: **отдельная таблица на каждую категорию**, у каждой таблицы — контрол «фильтрации по количеству элементов» в шапке и пагинация; заданное поведение кнопок «Добавить категорию», «Добавить технологию», «Редактировать технологию»; описанное модальное поведение Save/Delete. Поведение, не зафиксированное запросом и не вытекающее из текущего кода, помечено как **Требует уточнения (OPEN)** или **Предположение (A)**.

## Контекст

- Слой: `features/AdminSkills` (список + формы), композиция страницы — `src/pages/Admin/ui/AdminSkillsPage`; данные — `src/entities/Skill` + слайс `adminSkills` + storage `persistSkills` (persist-THEN-dispatch).
- Кит: `DataTable` (сортировка/пагинация контролируемые, `emptyState`-слот, **нет header-слота**), `Modal` (controlled, ESC/оверлей), `Select` (уже в обеих формах), `Badge`, `EmptyState`, `Heading`, `Form`, `Input`, `Textarea`, `Button`, `Toast`.
- Сегодняшнее состояние (факт): одна ПЛОСКАЯ DataTable на весь список (строки = технологии + placeholder пустых категорий), формы рендерятся ИНЛАЙН под списком, кнопка «Добавить технологию» — в строке первой категории в окне, фильтров нет, `PAGE_SIZE = 12`, удаление категории каскадное без отдельного предупреждения.
- Модель данных (факт): у `Technology` нет числовых полей-счётчиков (`name`, `iconSvg`, `invertInDark?`, `iconFilter?`).

## Структура интерфейса (целевая)

```
Section (data-testid="admin-skills")
├─ ErrorBoundary
├─ Шапка: Heading(h2) + Paragraph(hint) | Button «Добавить категорию» | Button «Сбросить»
├─ Блок категории × N (порядок из хранилища — вердикт OPEN-6):
│   ├─ Heading(h3): categoryName + Badge с видимой plural-формой счётчика (вердикт OPEN-8, ключ skillsCategoryCount)
│   ├─ Шапка блока: Button «Добавить технологию» (вердикт OPEN-3)
│   ├─ DataTable: caption = categoryName; колонки «Технология» (sortable) | «Действия»
│   │   ├─ верхняя строка DataTable: PageSizeGroup 5/10/20 (дефолт 5 — вердикт OPEN-1; рендерит kit, только при строках > 0)
│   │   └─ пустая категория → EmptyState (ключ skillsCategoryEmpty — вердикт OPEN-7), без контролов
│   └─ пагинация DataTable (локальное состояние блока — A4)
└─ Модалки: форма категории | форма технологии | подтверждение (tech/category/reset)
```

> Плейсмент (факт): «шапка таблицы» = строка блока категории НАД `DataTable` (header-слота у DataTable нет); сам `PageSizeGroup` рендерится `DataTable` первой строкой над телом (пропсы от контейнера блока) и гасится при 0 строк (`DataTable.tsx:150–151`).

## Поведение

### Страница

- Заголовок/hint/«Сбросить» — как сегодня (`adminSkillsTitle`, `adminSkillsHint`, `skillsReset` → confirm-модалка `skillsResetConfirm`; сброс удаляет ключ storage и возвращает сид, без тоста — факт текущего поведения, A11).
- Одновременно открыта максимум одна модалка (форма ИЛИ подтверждение) — предположение A12.

### Таблица категории

- `caption` визуально скрыт = `categoryName` (заголовок колонок: `technologies`/«Технологии», `skillsTableActions`/«Действия»).
- Сортировка по «Технология» — локально внутри таблицы, контролируемая (A9), цикл null→asc→desc→null, клик → страница 1.
- Счётчик категория→технологиям — Badge в заголовке блока с **видимой формой множественного числа** (ru: «1 технология»/«3 технологии»/«5 технологий», en: «1 technology»/«3 technologies») — вердикт OPEN-8 (число без расшифровки отклонено). Ключ **существующий** `skillsCategoryCount_one/_few/_many/_other` (в обеих локалях, используются витриной) — переиспользовать, `t(key, {count})` (без `count` i18next не выберет форму).
- Пустая категория → `EmptyState` в `emptyState`-слоте с ключом `skillsCategoryEmpty` (вердикт OPEN-7); текущий `skillsListEmpty` семантически не подходит («категорий нет» vs «в категории нет технологий»).

### Пагинация

- Независимая на каждую таблицу (A4): `page` и размер страницы — локальное состояние блока; `pageSizeOptions = [5, 10, 20]`, размер по умолчанию **5** (вердикт OPEN-1/OPEN-5, 2026-10-10); kit `Pagination` и `PageSizeGroup` рендерятся `DataTable`'ом (размер — первой строкой таблицы, при строках > 0; пропсы `pageSizeOptions`/`onPageSizeChange` прокидывает контейнер блока).
- Удаление/фильтрация/смена размера страницы → прижатие `page` к существующему `totalPages` (нет пустой страницы; паттерн clamp из плана Pagination §7) — A10.

### Фильтр «по количеству элементов» (контрол в шапке таблицы) — РЕШЕНО (вердикт 2026-10-10)

Дословное требование запроса: «Для каждой таблицы опиши фильтрацию по количеству элементов с контролом в шапке таблицы и пагинацию».

- **Вердикт владельца:** «фильтрация по 5, 10, 20» → интерпретация A: контрол = выбор количества элементов на странице, опции ровно **5 / 10 / 20**.
- Реализация: kit `PageSizeGroup` рендерится `DataTable` первой строкой каждой таблицы (пропсы от контейнера блока; `pageSizeOptions = [5, 10, 20]`, `onPageSizeChange`); kit гасит контрол при 0 строк; смена размера действует на СВОЮ таблицу и сбрасывает её страницу на 1. Размер по умолчанию — **5** (вердикт владельца 2026-10-10).
- Интерпретация B (пороговый фильтр по числовому признаку) отклонена как не имеющая данных (у `Technology` нет числовых полей).

### Модальное окно формы (create/edit) — РЕШЕНО (вердикт 2026-10-10)

> Вердикт владельца (OPEN-2: «переносить однозначно»): формы создания/редактирования переносятся в `Modal` (сегодня они инлайн под списком).

- **Открытие:** по кнопкам выше; `isOpen=true`; контент — существующая RHF-форма (валидация zod, `disabled={!isDirty}` на Save — факт).
- **Закрытие:** «Отмена» (`skillsCancel`) / ESC / клик по оверлею (`closeOnOverlayClick`) → `isOpen=false`, изменения не сохраняются, без подтверждения о несохранённых правках (A8). Успешный Save тоже закрывает (A7 — отличие от текущего create-поведения, где инлайн-форма оставалась открытой).
- **«Сохранить» (`skillsSave`, submit):** 1) zod-валидация (ошибки — `Paragraph role="alert"`, ничего не сохранено, модалка открыта); 2) `persistSkills(next)` → `false`: тост `skillsPersistError`, модалка открыта, состояние стора не тронуто; 3) успех: dispatch add/update → тост `skillsSaved` → закрыть модалку. Порядок persist-THEN-dispatch — обязательный (факт текущего контракта).

### Модальное окно подтверждения («Удалить»)

- Открытие: «Удалить» в строке технологии (`kind:'technology'`) / действиях категории (`kind:'category'`) / «Сбросить» (`kind:'reset'`) — как сегодня.
- Содержимое: title `skillsDelete`/`skillsReset`; текст подтверждения передаётся через **`subtitle`** модалки (kit `ModalRoot` строит `aria-describedby` только из него — `ModalRoot.tsx:44`, иначе у кнопки «Удалить» нет связанного описания, GitHub Primer Accessibility); кнопки «Отмена» + danger «Удалить» (`loading` во время persist), фокус после открытия — на «Отмена» (destrucive-confirm паттерн).
- Называние: текст подтверждения (через `subtitle`) **называет удаляемую сущность** — «Удалить React?»; для категории — текст уточнения OPEN-4 (технологии удаляются вместе + количество при N > 0) с именем категории (вердикт OPEN-10 «Вариант А»). Кнопка остаётся короткой **«Удалить»** (`skillsDelete`), «Отмена» — прежняя.
- «Удалить» (confirm): `persistSkills` списком без цели → dispatch `deleteTechnology`/`deleteSkillCategory` → тост `skillsDeleted` → закрыть.
- Ошибка storage при confirm: тост `skillsPersistError` + **модалка остаётся открытой** (вердикт OPEN-9 «унифицируем» — единообразно с формой, можно повторить); данные не изменены.
- Семантика категории: технологии удаляются вместе с категорией (факт); текст подтверждения для категории уточняется (вердикт OPEN-4): отдельный ключ сообщает, что технологии категории тоже будут удалены, и при `N > 0` показывает количество (ru-plural `_one/_few/_many`, `{{count}}`); для категории без технологий — без количества. Удаление технологии и сброс — прежний `skillsConfirmDelete`/`skillsResetConfirm`.
- «Отмена»: закрыть без изменений.
- Все ветки колбэков defensive (проверяют сопоставимость kind/цели до dispatch) — уточнение контракта A12 («открытая форма относится к удалённой записи» недостижима, пока модалки mutually exclusive), факт тестов `SkillsEditorList.test`.

### Select

- Уже используются и сохраняются: ключ категории (`SkillCategoryForm`), иконка (`TechnologyForm`).
- Контрол размера страницы — `PageSizeGroup` (kit-компонент под эту задачу), НЕ `Select`; `Select` остаётся для ключа категории и иконки.

### i18n

- Все строки — через `t()`; **переиспользовать существующие ключи**, где они уже есть: счётчик `skillsCategoryCount_one/_few/_many/_other` (обе локали, витрина `SkillItem.tsx:52`), `skillsDelete`/`skillsReset`. Новыми будут только: `skillsCategoryEmpty` (вердикт OPEN-7) + тексты подтверждения с именем сущности через interpolation `{{name}}` (вердикты OPEN-4 + OPEN-10) + подписи контролов/фильтра. Всё новое — в `en.json` + `ru.json`, паритет закреплён тестом; захардкоженных строк нет (критерий ниже).
