# SPEC — features/AdminSkills (редактирование блока «Навыки»)

> Единственная истина для этого блока (spec-driven workflow: AGENTS.md, раздел Spec-driven features). Статусы: `draft` → `approved` → `done`.
> Исходный план: vault `wiki/plan/plan_admin_panel_edit.md`, rev.1 (фаза 1 — блок «Навыки»). Companion: [TODO.md](./TODO.md).
> Язык: русский (правило владельца). Все user-facing строки в коде — i18n-ключи en+ru.

## Цель

Переработать админ-блок «Навыки» (`/admin/skills`) по продуктовому запросу: **отдельная таблица на каждую категорию**, у каждой таблицы — контрол «фильтрации по количеству элементов» в шапке и пагинация; заданное поведение кнопок «Добавить категорию», «Добавить технологию», «Редактировать технологию»; описанное модальное поведение Save/Delete. Поведение, не зафиксированное запросом и не вытекающее из текущего кода, помечено как **Требует уточнения (OPEN)** или **Предположение (A)**.

## Контекст

- Слой: `features/AdminSkills` (список + формы), композиция страницы — `src/pages/Admin/ui/AdminSkillsPage`; данные — `src/entities/Skill` + слайс `adminSkills` + storage `persistSkills` (persist-THEN-dispatch).
- Кит: `DataTable` (сортировка/пагинация контролируемые, `emptyState`-слот, **нет header-слота**), `Modal` (controlled, ESC/оверлей), `Select` (уже в обеих формах), `Badge`, `EmptyState`, `Heading`, `Form`, `Input`, `Textarea`, `Button`, `Toast`.
- Сегодняшнее состояние (факт): одна ПЛОСКАЯ DataTable на весь список (строки = технологии + placeholder пустых категорий), формы рендерятся ИНЛАЙН под списком, кнопка «Добавить технологию» — в строке первой категории в окне, фильтров нет, `PAGE_SIZE = 12`, удаление категории каскадное без отдельного предупреждения.
- Модель данных (факт): у `Technology` нет числовых полей-счётчиков (`name`, `iconSvg`, `invertInDark?`, `iconFilter?`).

## Структура интерфейса (целевая)

```
Section (data-testid="admin-skills")
├─ ErrorBoundary
├─ Шапка: Heading(h2) + Paragraph(hint) | Button «Добавить категорию» | Button «Сбросить»
├─ Блок категории × N (порядок — A2):
│   ├─ Heading(h3): categoryName + Badge со счётчиком (A5)
│   ├─ Шапка блока: PageSizeGroup (опции 5/10/20 — вердикт OPEN-1) | Button «Добавить технологию» (A3)
│   ├─ DataTable: caption = categoryName; колонки «Технология» (sortable) | «Действия»
│   │   └─ пустая категория → EmptyState (A6)
│   └─ пагинация DataTable (локальное состояние блока — A4)
└─ Модалки: форма категории | форма технологии | подтверждение (tech/category/reset)
```

> Плейсмент (факт): «шапка таблицы» = строка блока категории НАД `DataTable` (header-слота у DataTable нет).

## Поведение

### Страница

- Заголовок/hint/«Сбросить» — как сегодня (`adminSkillsTitle`, `adminSkillsHint`, `skillsReset` → confirm-модалка `skillsResetConfirm`; сброс удаляет ключ storage и возвращает сид, без тоста — факт текущего поведения, A11).
- Одновременно открыта максимум одна модалка (форма ИЛИ подтверждение) — предположение A12.

### Таблица категории

- `caption` визуально скрыт = `categoryName` (заголовок колонок: `technologies`/«Технология», `skillsTableActions`/«Действия»).
- Сортировка по «Технология» — локально внутри таблицы, контролируемая (A9), цикл null→asc→desc→null, клик → страница 1.
- Счётчик категория→число технологий — Badge в заголовке блока (A5, OPEN-8).
- Пустая категория → `EmptyState` в `emptyState`-слоте (A6, OPEN-7: текущий `skillsListEmpty` семантически не подходит).

### Пагинация

- Независимая на каждую таблицу (A4): `page` и размер страницы — локальное состояние блока; `pageSizeOptions = [5, 10, 20]`, размер по умолчанию **10** (вердикт OPEN-1/OPEN-5; дефолт — предположение A4); kit `Pagination` рендерится `DataTable`'ом, `PageSizeGroup` — в шапке блока.
- Удаление/фильтрация/смена размера страницы → прижатие `page` к существующему `totalPages` (нет пустой страницы; паттерн clamp из плана Pagination §7) — A10.

### Фильтр «по количеству элементов» (контрол в шапке таблицы) — РЕШЕНО (вердикт 2026-10-10)

Дословное требование запроса: «Для каждой таблицы опиши фильтрацию по количеству элементов с контролом в шапке таблицы и пагинацию».

- **Вердикт владельца:** «фильтрация по 5, 10, 20» → интерпретация A: контрол = выбор количества элементов на странице, опции ровно **5 / 10 / 20**.
- Реализация: kit `PageSizeGroup` в шапке блока каждой таблицы (`pageSizeOptions = [5, 10, 20]`, `onPageSizeChange`); смена размера действует на СВОЮ таблицу и сбрасывает её страницу на 1. Размер по умолчанию — 10 (предположение A4; в вердикте не назван).
- Интерпретация B (пороговый фильтр по числовому признаку) отклонена как не имеющая данных (у `Technology` нет числовых полей).

### Модальное окно формы (create/edit) — ТРЕБУЕТ УТОЧНЕНИЯ переноса (OPEN-2)

> Предположение A1: формы переносятся в `Modal` (запрос описывает модальное поведение Save; сегодня они инлайн).

- **Открытие:** по кнопкам выше; `isOpen=true`; контент — существующая RHF-форма (валидация zod, `disabled={!isDirty}` на Save — факт).
- **Закрытие:** «Отмена» (`skillsCancel`) / ESC / клик по оверлею (`closeOnOverlayClick`) → `isOpen=false`, изменения не сохраняются, без подтверждения о несохранённых правках (A8). Успешный Save тоже закрывает (A7 — отличие от текущего create-поведения, где инлайн-форма оставалась открытой).
- **«Сохранить» (`skillsSave`, submit):** 1) zod-валидация (ошибки — `Paragraph role="alert"`, ничего не сохранено, модалка открыта); 2) `persistSkills(next)` → `false`: тост `skillsPersistError`, модалка открыта, состояние стора не тронуто; 3) успех: dispatch add/update → тост `skillsSaved` → закрыть модалку. Порядок persist-THEN-dispatch — обязательный (факт текущего контракта).

### Модальное окно подтверждения («Удалить»)

- Открытие: «Удалить» в строке технологии (`kind:'technology'`) / действиях категории (`kind:'category'`) / «Сбросить» (`kind:'reset'`) — как сегодня.
- Содержимое: title `skillsDelete`/`skillsReset`, текст `skillsConfirmDelete`/`skillsResetConfirm`; кнопки «Отмена» + danger «Удалить» (`loading` во время persist).
- «Удалить» (confirm): `persistSkills` списком без цели → dispatch `deleteTechnology`/`deleteSkillCategory` → тост `skillsDeleted` → закрыть; если открытая форма относится к удалённой записи — закрыть её (факт `onCategoryDeleted`/`onTechnologyDeleted`).
- Семантика категории: технологии удаляются вместе с категорией (факт); вопрос предупреждения о масштабе — OPEN-4.
- «Отмена»: закрыть без изменений.

### Select

- Уже используются и сохраняются: ключ категории (`SkillCategoryForm`), иконка (`TechnologyForm`).
- Контрол размера страницы — `PageSizeGroup` (kit-компонент под эту задачу), НЕ `Select`; `Select` остаётся для ключа категории и иконки.

### i18n

- Все строки — через `t()`; новые ключи (счётчик, пустая категория, подписи контролов) добавляются в `en.json` + `ru.json`, паритет закреплён тестом. Жёстко захардкожных строк — нет (критерий ниже).

## Критерии приёмки

> Часть критериев помечена «(после OPEN-x)» — они активируются вердиктом владельца.

### Структура

- [ ] На `/admin/skills` каждая категория из `selectAllSkillsData` отрисована отдельным блоком со своей таблицей (общей плоской таблицы больше нет).
- [ ] У каждой таблицы `caption` = `categoryName`; колонки «Технология» и «Действия».
- [ ] Блоки категорий следуют в порядке из хранилища (после OPEN-6 / A2).
- [ ] Заголовок блока (h3) содержит `categoryName` и Badge со счётчиком технологий (после OPEN-8 / A5).
- [ ] Пустая категория показывает EmptyState в теле своей таблицы (после OPEN-7 / A6).

### Кнопки и модалки

- [ ] «Добавить категорию» в шапке секции открывает модалку create-формы; в `Select` ключа нет уже занятых категорий.
- [ ] «Добавить технологию» (шапка блока категории — после OPEN-3/A3) открывает модалку create-формы с фиксированной категорией.
- [ ] «Редактировать технологию» в строке открывает предзаполненную модалку; после Save с новым именем строка показывает новое имя, старое больше не встречается в этой категории.
- [ ] Валидный Save: persist → dispatch → тост `skillsSaved` → модалка закрыта; перезагрузка страницы показывает сохранённое.
- [ ] Невалидный Save: ошибки видны, ничего не сохранено, модалка открыта.
- [ ] Ошибка storage: тост `skillsPersistError`, модалка открыта, стор не изменён.
- [ ] Cancel/ESC/оверлей: модалка закрыта, изменения не сохранены.
- [ ] «Удалить» (confirm) технологии: строка исчезла, тост `skillsDeleted`, запись отсутствует в storage после перезагрузки.
- [ ] «Удалить» (confirm) категории: категория и её технологии исчезли; открытая форма этой категории закрыта (каскадный текст — после OPEN-4).
- [ ] «Сбросить» → confirm → сид восстановлен (существующее поведение, A11).

### Таблицы: сортировка, пагинация, фильтр

- [ ] Клик по «Технология» сортирует строки СВОЕЙ таблицы; другие таблицы не меняются; страница сбрасывается на 1 (после A9).
- [ ] При строках больше PAGE_SIZE у таблицы появляется пагинация; `page` независим на блок (после A4).
- [ ] Удаление строки на последней странице прижимает `page` к новому `totalPages` — пустой страницы нет (после A10).
- [ ] В шапке блока каждой таблицы — `PageSizeGroup` с опциями 5/10/20 (по умолчанию 10); смена размера меняет строки только своей таблицы и сбрасывает её страницу на 1.
