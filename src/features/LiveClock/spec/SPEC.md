## Что делает

Временная тестовая фича для первого полного прогона цикла SPEC/TODO (workflow `06-spec-workflow.md`, статус `proposed` → `verified` по её закрытии). Показывает локальное время пользователя на главной странице: подпись «Local time» / «Локальное время» и часы, тикающие раз в секунду через `Intl.DateTimeFormat`. Фича намеренно маленькая и изолированная: после `done` удаляется отдельной задачей вместе с этой папкой `spec/`.

## Критерии готовности

- [x] `HomePage` рендерит блок с `data-testid="live-clock"` в конце `<main>` (после Contact, без изменения порядка существующих секций)
- [x] Время форматируется через `Intl.DateTimeFormat` с языком из i18n (не хардкод-строка, не ручная сборка `HH:MM:SS`)
- [x] Часы обновляются не реже раза в секунду; интервал очищается при размонтировании (тест с fake timers: после unmount тик не меняет DOM)
- [x] Подпись «Local time» / «Локальное время» приходит через `t()`; ключи есть в `en.json` И `ru.json` (существующий `locales-parity.test.ts` зелёный)
- [x] Слайс подключён через публичный API `features/LiveClock` (никаких deep-import из `pages`)
- [x] `Nav` не меняется: `EXPECTED_ANCHORS` и якоря секций идентичны до/после (якорь для LiveClock НЕ заводится)
- [x] Компонентный тест зелёный: первичный рендер, обновление тика, cleanup, наличие подсказки времени (`aria-label`/видимая подпись связаны со значением)
- [x] `npm run validate` зелёный (type-check, lint, stylelint, vitest + coverage, `check:public-api`)

## Вне скоупа

- Якорь/ссылка в `widgets/Nav` — блок не навигационный
- Настройка таймзоны, формата 12/24, вторых часовых поясов — только локальное время браузера
- Новые дизайн-токены и палитра — используются существующие токены/стили слайса
- Данные из Redux/store — фича stateless (помещение в store = отдельная фича)
- Админ-редактирование контента (`features/AdminAbout` и т.п.) — не затрагивается
- Удаление фичи — отдельная задача после `done` (не в этой)
