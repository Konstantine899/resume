# SPEC — shared/ui/Table

> Единственная истина для этого компонента (spec-driven workflow: AGENTS.md, раздел Spec-driven features). Статусы: `draft` → `approved` → `done`.
> Фаза A создана вручную из `scripts/createSlices/templates/spec.mjs` — у генератора нет слоя `shared` (`scripts/fsd-layers.json` → `generatorLayers`); `--scaffold` (фаза B) для kit-компонентов выполняется вручную. Исходный план: vault `wiki/plan/plan_kit_table.md`, рев.3.

## Цель

Презентационная таблица-примитив: только семантическая разметка, нулевое поведение. Она даёт каждому списку настоящую таблицную семантику — сегодня в `src/` ноль элементов `<table>` (аудит `wiki/research/admin-ux-audit.md`) — и является базовым слоем для `shared/ui/DataTable`.

## Контекст

- Слой: `shared` (FSD), компонент: `ui/Table`; Redux: нет; зависимости: нет (kit `Skeleton` может заполнять слот загрузки).
- Соглашение об импорте: `import { Table } from '@/shared/ui/Table'` — корневого барреля `src/shared/ui/index.ts` не существует (проверяет `check:public-api`); пока нет потребителя, компонент не попадает в main-чанк витрины.
- Сортировка, пагинация и выбор — территория DataTable (план A2) — Table их никогда не рендерит.
- **Прокладка `ariaSort` (rev.4, 2026-10-10, план DataTable WU-5):** в `Column` добавлено разметочное поле `ariaSort?: 'ascending' | 'descending' | 'none'` — pass-through одноимённого атрибута `aria-sort` на `<th>`. Причина: APG требует `aria-sort` именно на `<th>`, а DataTable до `<th>` не дорисовывает (Table владеет `thead`). Это АТРИБУТ, не поведение: Table по-прежнему не знает ни о кнопках, ни о цикле сортировки — «какая колонка/направление» решает DataTable и прокидывает значение. Поле опционально: без него `aria-sort` не рендерится (существующий тест «no sort buttons/aria-sort» на фикстурах без поля остаётся зелёным).

## Критерии приёмки

- [ ] `getByRole('table', { name: <caption> })` находит элемент — у `<table>` есть `<caption>`, визуально скрытый миксином `.visually-hidden`, но доступный SR.
- [ ] Каждый `<th>` рендерится с `scope="col"`.
- [ ] Проп `loading` → `aria-busy="true"` на элементе таблицы.
- [ ] Пустые `rows` → рендерится слот `emptyState` вместо пустого тела таблицы.
- [ ] Колонка без `render` → ячейка показывает `String(row[key])`.
- [ ] `align` (`left|right|center`) → соответствующий CSS-модификатор на заголовке и ячейках этой колонки.
- [ ] Колонка с `hideOnMobile` не отображается при вьюпорте 390px; обёртка остаётся горизонтально прокручиваемой.
- [ ] Обёртка прокрутки — `role="region"` + `aria-label={caption}` + `tabindex="0"` с `overflow-x: auto` (axe `scrollable-region-focusable` чисто).
- [ ] Отрендеренная таблица не содержит ни одного заголовочного элемента (h1–h6) — в фикстурах ячеек `<strong>`/ссылки; тест проверяет отсутствие (план A6).
- [ ] Table не рендерит ни кнопок сортировки, ни пагинации, ни выбора строк (тест без поведения, план A2).
- [ ] (rev.4) Колонка с `ariaSort: 'ascending' | 'descending' | 'none'` → `<th>` получает `aria-sort` этим значением; колонка без поля — атрибут отсутствует (тест на richColumns без поля остаётся зелёным).
- [ ] Сторисы покрывают пять фикстур с реальными ячейками (иконка, бейдж, двухстрочная, ссылка, действия), обе темы, загрузку, emptyState и 390px с `hideOnMobile`.
- [ ] `scripts/axe-stories-check.mjs` прогоняется по сторисам Table и сообщает 0 новых нарушений (правила best practice, не только wcag*a/aa).
- [ ] `npm run build` + `check:bundle` в пределах лимитов; маркер Table отсутствует в main-чанке витрины.

## Что не входит

- Сортировка, пагинация, выбор, фильтрация → `plan_kit_datatable.md`.
- Режимы плотности строк (план OPEN-2) и липкий `thead` (план OPEN-5).
- Адаптивная раскладка карточками в стопку — отклонено, теряется таблицная семантика (план A5).
- Замена сетки `StatCard` на дашборде таблицей (план §1).

## Риски

- PurgeCSS удаляет SCSS-классы, которые не захардкожены в JSX и не обёрнуты в `:global` — проверять собранный CSS после `npm run build` (gotcha `resume-css-global-keyframes`).
- Базовые нарушения axe (`nested-interactive`, `scrollable-region-focusable`) нельзя перетаскивать в компонент.
- Двухуровневые данные Skills (группы категорий): компонент остаётся плоским — тесты НЕ должны фиксировать «ровно один tbody» (план §7).
