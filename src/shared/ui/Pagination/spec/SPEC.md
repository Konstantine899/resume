# SPEC — shared/ui/Pagination

> Единственная истина для этого компонента (spec-driven workflow: AGENTS.md, раздел Spec-driven features). Статусы: `draft` → `approved` → `done`.
> Фаза A создана вручную из `scripts/createSlices/templates/spec.mjs` (нет `shared` в `generatorLayers`); фаза B выполняется вручную. Исходный план: vault `wiki/plan/plan_kit_pagination.md`, рев.3.

## Цель

Презентационный контрол пагинации, чтобы растущие списки (Skills = 42 строки) можно было разбивать на страницы — сегодня пагинации нет нигде в `src/` (grep `currentPage|pageSize|pagination` → 0; аудит P1 #12).

## Контекст

- Слой: `shared` (FSD), компонент: `ui/Pagination`; Redux: нет; зависимости: kit `Button` (переиспользуется, не дублируется).
- Полностью презентационный (план A2): пропсы `page`/`totalPages`/`onPageChange`, состояние живёт у потребителя — сначала фича, потом URL (deep-links = аудит P0 #3). Именно это делает один и тот же компонент переиспользуемым во всех пяти списках.
- Все строки — i18n (en+ru): метка навигации, aria-labels prev/next (план A4).

## Критерии приёмки

- [ ] `totalPages < 1` (пустой/невалидный диапазон) → компонент ничего не рендерит (null). `totalPages = 1` → полный ряд `‹ 1 ›`: страница «1» с `aria-current`, обе стрелки `disabled` (директива владельца 2026-10-09: контролы не должны исчезать под пользователем; правило A3 «null при 1» пересмотрено).
- [ ] Рендерит `<nav>` с i18n `aria-label` (ключ есть и в `en.json`, и в `ru.json`, тест паритета зелёный).
- [ ] Активная страница — некликабельный элемент с `aria-current="page"`; клик по любому другому числу вызывает `onPageChange` с этим числом.
- [ ] Кнопки prev/next используют kit `Button` и отключены на первой/последней странице.
- [ ] Окно соседей: страница 5 из 10 при `siblings` по умолчанию → `1 … 4 5 6 … 10`; края сворачиваются в многоточие, первая/последняя страница всегда достижимы.
- [ ] aria-labels prev/next берутся из i18n-ключей в обеих локалях (без захардкоженных строк).
- [ ] Сторисы: одна страница, много страниц, обе темы.
- [ ] Пилот (OPEN-1): админ-список Skills разбивается на страницы на стороне клиента — после удаления или фильтрации, когда текущая страница выходит за пределы, контейнер прижимает `page` к `totalPages` (нет пустой страницы; clamp живёт в контейнере фичи, план §7).
- [ ] Пилот: axe `/admin/skills` → 0 новых нарушений; `check:bundle` в пределах лимитов.

## Что не входит

- Селектор `pageSize` (план OPEN-2 — состояние остаётся снаружи; проп можно добавить позже, не ломая API).
- Собственное управление состоянием или синхронизация с URL (план A2).
- Кнопки перехода к странице / первая-последняя (не запрошены; многоточия на краях достаточно).

## Риски

- Конфликт параллельных пилотов: пилот DataTable трогает тот же список Skills — правило последовательности в плане WU-3 (Pagination вливается первым, либо его пилот встраивается в пилот DataTable по вердикту владельца).
- Переделка сверх нужного: без триггера владельца (рост списка) пагинация хуже поиска и фильтрации — пилот не должен поставлять спекулятивный UI.
