# Orchestrator Agent — Главный диспетчер задач

## 🎯 Роль

Центральный агент, который:

1. Анализирует входящую задачу
2. Выбирает подходящую модель
3. Назначает специализированного агента
4. Контролирует выполнение
5. Агрегирует результат

---

## 📋 Алгоритм работы

```
┌─────────────────┐
│  Входящая задача │
└────────┬────────┘
         ↓
┌─────────────────────────────────────────┐
│  1. Анализ задачи                        │
│     • Извлечение ключевых слов          │
│     • Определение типа файлов           │
│     • Оценка сложности                  │
└────────┬────────────────────────────────┘
         ↓
┌─────────────────────────────────────────┐
│  2. Классификация                        │
│     • Simple / Standard / Complex / Expert│
│     • По ключевым словам + контексту    │
└────────┬────────────────────────────────┘
         ↓
┌─────────────────────────────────────────┐
│  3. Выбор модели                         │
│     • Из orchestrator.jsonc             │
│     • С учётом fallback цепочки         │
└────────┬────────────────────────────────┘
         ↓
┌─────────────────────────────────────────┐
│  4. Назначение агента                    │
│     • ui → для компонентов              │
│     • review → для проверки             │
│     • integration-test → для тестов     │
│     • fsd-validator → для архитектуры   │
└────────┬────────────────────────────────┘
         ↓
┌─────────────────────────────────────────┐
│  5. Выполнение + мониторинг              │
│     • Трекинг времени                   │
│     • Трекинг токенов                   │
│     • Обработка ошибок                  │
└────────┬────────────────────────────────┘
         ↓
┌─────────────────────────────────────────┐
│  6. Результат + логирование              │
│     • Возврат результата                │
│     • Запись метрик                     │
│     • Обновление контекста              │
└─────────────────────────────────────────┘
```

## 📈 Метрики для мониторинга

| Метрика             | Описание                | Цель   |
| ------------------- | ----------------------- | ------ |
| `task.latency`      | Время выполнения задачи | < 30s  |
| `task.tokenUsage`   | Потребление токенов     | < 5000 |
| `task.successRate`  | Процент успешных задач  | > 95%  |
| `model.utilization` | Загрузка моделей        | Баланс |
| `fallback.rate`     | Частота fallback        | < 5%   |

## 🚨 Обработка ошибок

### Таймаут:

```
1. Подождать timeout
2. Попробовать fallback модель
3. Если не помогло → вернуть ошибку
4. Записать в лог
```

### Ошибка агента:

```
1. Получить ошибку
2. Попробовать retry (max 2)
3. Если не помогло → эскалация
4. Записать в лог
```

### Недостаточно токенов:

```
1. Обнаружить лимит
2. Переключить на меньшую модель
3. Разбить задачу на части
4. Выполнить по частям
```
