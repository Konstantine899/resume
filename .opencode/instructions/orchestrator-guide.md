# Model Orchestrator — Система классификации задач

## 🎯 Как работает

Оркестратор анализирует запрос и выбирает модель по 3 критериям:

1. **Ключевые слова** в запросе
2. **Тип файлов**, с которыми работаем
3. **Контекст задачи** (сложность, риски)

---

## 📊 Матрица решений

| Уровень      | Модель        | Токены | Время | Когда использовать                  |
| ------------ | ------------- | ------ | ----- | ----------------------------------- |
| **Simple**   | deepseek:1.3b | 500    | 10s   | Правки, комментарии, форматирование |
| **Standard** | qwen:7b       | 2000   | 30s   | Компоненты, тесты, багфиксы         |
| **Complex**  | qwen:32b      | 8000   | 60s   | Рефакторинг, интеграции, отладка    |
| **Expert**   | deepseek:671b | 16000  | 120s  | Архитектура, аудит, прод-баги       |

---

## 🏷️ Теги для классификации

### Simple (быстрая модель)

```
#typo #format #rename #comment #explain #style #minor
```

### Standard (баланс)

```
#component #test #feature #bugfix #refactor #types #ui
```

### Complex (мощная)

```
#architecture #debug #migration #integration #performance #state
```

### Expert (максимальная)

```
#security #audit #design #system #production #critical #review
```

---

## 📝 Примеры использования

### В запросе явно:

```
"Создай компонент Button #component #ui"
→ Standard (qwen:7b)

"Проведи аудит безопасности #security #audit"
→ Expert (deepseek:671b)
```

### Авто-детект по ключевым словам:

```
"Исправь опечатку в названии переменной"
→ Simple (ключевое слово: "опечатку")

"Оптимизируй производительность рендеринга"
→ Complex (ключевое слово: "производительность")
```

### По типу файлов:

```
Работа с package.json → Expert
Работа с *.config.* → Expert
Работа с *.test.* → Complex
Работа с *.tsx → Standard
Работа с *.md → Simple
```

---

## 🔄 Fallback цепочка

Если модель не отвечает:

```
Expert (timeout 120s)
    ↓ timeout
Complex (timeout 60s)
    ↓ timeout
Standard (timeout 30s)
    ↓ timeout
Simple (timeout 10s)
```

---

## 📈 Метрики

Оркестратор логирует:

- Какую модель выбрали
- Почему (какой триггер)
- Время выполнения
- Успешность
- Потребление токенов

Лог: `.opencode/logs/orchestrator.log`

## 🎯 Best Practices

### ✅ Правильно:

```
"Создай форму логина #component #feature"
"Проведи code review #review #security"
"Исправь тип #types #minor"
```

### ❌ Неправильно:

```
"Сделай всё"  ← непонятно, какая модель нужна
"Что-то сломалось" ← нет контекста
```

---

## 🔧 Ручное переопределение

Можно явно указать модель:

```
"Создай компонент @expert"
"Исправь баг @complex"
"Отформатируй @simple"
```

Приоритет: **Явный тег > Авто-детект > Дефолт**
